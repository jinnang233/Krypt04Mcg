# 关键路径安全审计（2026-10-08）

范围：主项目共享的加密封装、混合 KEM/签名、包编解码、会话握手与重放账本、密钥信任和本地存储，以及 Fabric/NeoForge 的聊天接收和可选文件/数据通道。此次为人工代码审查和针对性回归验证，不是独立密码学审计或完整渗透测试。

## 已确认并修复

### 分片重组可用性问题（中等，拒绝服务）

聊天分片在解密和签名验证前进入 `FragmentReassembler`。原实现有两个可复现的问题：

- 每个新的分片索引都会刷新 `lastTouched`。攻击者可间隔发送新索引，让不完整消息远超配置的两分钟期限占用缓存；重复同一个索引虽不续期，却不能防止这种慢速发送。
- 缓存达到容量后，新消息 ID 会驱逐已有消息。连续发送新的不完整消息，可以让正常接收中的消息丢失已缓存的分片。

修复：按首次接收时间设定固定到期时间；容量耗尽时拒绝新的组装任务，继续允许已有任务接收分片。不改变已发送包的加密格式。到期清理仍由现有 cleanup/receive 调用执行，不新增后台线程。

### 畸形聊天分片提前占用缓存（输入加固）

`FragmentService.isFragment` 原来只验证数字索引关系，任意消息 ID、非法 Base64URL 字符和超过接收上限的总数都可能通过识别。错误要等到后续重组或包验证才暴露。

修复：提前验证 32 位十六进制 ID、十进制索引、1–512 的总数和无填充 Base64URL 字符集。保留空字节串的原有分片往返行为。有效的自定义前缀、乱序分片和重复分片继续受现有测试覆盖。

## 其他审查结果与边界

- 签名解密路径绑定声明发送者与签名公钥所有者；紧凑包的 AAD 包含时间戳和算法字段。混合签名验证要求两个分量均有效，未发现本次可证实的单分量降级绕过。
- 会话握手绑定双方身份、指纹、请求 ID 和持久化 epoch；会话消息绑定 session ID 和序号。现有回归测试验证这些边界，不代表所有算法参数均已审计。
- 私密存储拒绝符号链接路径，使用 AES-GCM 和受限本地文件权限；文件接收受大小限制，接收后的文件名被净化并加随机前缀，保存需要用户接受。
- 固定期限和拒绝驱逐保护已经接收的消息，不能消除持续流量洪泛或攻击者提前占满所有槽位。单发送者配额、传输层流控和单调时钟到期可作为后续加固；本次不宣称全面解决拒绝服务。
- 未验证实际游戏服务器联机、Windows DPAPI、依赖供应链或所有后量子算法的安全性质。

## 验证
